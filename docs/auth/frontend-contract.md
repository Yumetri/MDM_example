# 인증 프런트엔드 계약

구현 티켓: [#48](https://github.com/Yumetri/MDM_example/issues/48).
인증 정본 #22와 세션 #37, 가입 #38, 비밀번호 수명주기 #39의 API 계약을 따른다.

## 구현 전 검수로 확정한 사항

### Web Locks 필수 지원

2026-09-20 검수에서 탭 간 세션 갱신 조정과 미지원 브라우저의 처리를 다음과 같이 승인했다.

- Web Locks API를 사용해 같은 사이트의 여러 탭이 세션 갱신을 동시에 실행하지 않도록 한다.
- Web Locks를 사용할 수 없는 브라우저에서는 인증 기능을 진행하지 않고 지원 브라우저
  안내를 표시한다.
- 미지원 브라우저를 위한 별도의 탭 간 조정 방식은 이번 구현에 추가하지 않는다.

### 세션 쿠키 변경 요청의 공통 잠금

2026-09-21 검수에서 Web Locks의 적용 범위를 다음과 같이 승인했다.

- 로그인, 가입 완료, 세션 갱신, 로그아웃, 로그인 상태 비밀번호 변경과 비밀번호 재설정
  완료는 모두 같은 Web Lock을 사용한다.
- 한 탭이 위 요청을 처리하는 동안 다른 탭은 기다린다. 잠금을 얻은 뒤 현재 CSRF cookie를
  읽어 요청하고, 응답 처리가 끝난 뒤 잠금을 해제하여 다음 요청이 최신 cookie를 사용하게 한다.
- 이메일만 제출하는 가입 신청과 비밀번호 재설정 신청은 잠금 대상에서 제외한다.
- 백엔드의 cookie·Origin·CSRF, refresh 회전 및 비밀번호 변경 계약은 유지한다.

### 탭 간 로그인 상태 동기화

2026-09-21 검수에서 다른 탭의 로그인 상태와 대기 요청을 다음과 같이 처리하기로 승인했다.

- 로그인·계정 변경이 성공하면 다른 탭은 이전 인증 정보를 지우고, 현재 세션을 확인한 뒤
  화면을 갱신한다.
- 로그아웃·비밀번호 재설정 완료가 성공하면 다른 탭도 인증 정보를 지우고 로그인 화면으로
  전환한다.
- 계정 변경 중 잠금을 기다리던 요청은 취소하고 다시 제출하도록 안내한다. 이전 계정에서
  시작한 요청을 새 계정으로 실행하지 않는다.
- 탭 사이에는 상태 변경 알림만 전달한다. token·비밀번호는 전달하거나 저장하지 않는다.

2026-09-23 검수에서도 로그아웃 성공 시 같은 사이트의 다른 열린 탭이 메모리의 access
token과 사용자 정보를 지우고 로그인 화면으로 전환하는 정책을 확인했다. 이 처리는
프런트엔드의 인증 상태를 정리하며, 서버에서 이미 발급한 JWT의 만료 정책은 유지한다.

### 필요한 시점의 세션 갱신

2026-09-23 검수에서 자동 갱신 시점을 다음과 같이 승인했다.

- 페이지 시작 시 refresh로 세션을 복구한다.
- 이후 인증 요청에 필요한 access token이 만료됐을 때 세션을 갱신한다.
- 주기적인 타이머를 사용해 사용하지 않는 탭의 세션을 계속 갱신하지 않는다.
- 다른 탭의 로그인·계정 변경 후 현재 세션을 확인하는 승인된 동작은 유지한다.

### 탭 동기화 상태 표식

2026-09-23 검수에서 탭 동기화를 위한 저장 범위를 다음과 같이 승인했다.

- `localStorage`에는 인증정보가 아닌 무작위 변경 ID와 상태 변경 종류만 저장한다.
- token·비밀번호·이메일·사용자 ID 등 인증정보와 사용자 정보는 저장하지 않는다.
- 잠금을 얻거나 탭이 다시 활성화될 때 표식을 확인해 다른 탭의 계정 변경을 감지하고,
  이전 계정에서 대기하던 요청을 취소한다.
- 저장소를 사용할 수 없으면 안전한 탭 동기화를 할 수 없다는 안내 후 인증 작업을 중단한다.

### 비밀번호 변경 후 다른 탭의 처리

2026-09-23 검수에서 로그인 상태 비밀번호 변경 성공 후의 처리를 다음과 같이 승인했다.

- 다른 탭도 기존 access token을 지우고 새 세션을 확인해 로그인 상태를 유지한다.
- 비밀번호 변경 전에 잠금을 기다리던 요청은 취소하고 다시 제출하도록 안내한다.
- 백엔드의 새 refresh family·CSRF cookie 발급 계약을 그대로 사용한다.

### 최소 화면 구성과 성공 후 이동

2026-09-23 검수에서 다음 화면 구성을 승인했다.

- 로그인·가입 신청·비밀번호 재설정 신청은 각각 별도 화면으로 제공한다.
- 로그인·가입 완료 후에는 이름·이메일·현재 권한, 비밀번호 변경과 로그아웃을 제공하는
  내 계정 화면으로 이동한다.
- 비밀번호 재설정 완료 후에는 로그인 화면으로 안내한다.
- 이메일 링크의 가입 완료·재설정 완료 경로는 기존 명세를 유지한다.

### 완료 이후 세션 확인 실패

2026-09-23 검수에서 작업 완료와 후속 조회 실패를 구분하기로 승인했다.

- 가입·비밀번호 변경 API가 성공한 뒤 세션 갱신 또는 내 정보 조회가 실패하면,
  원래 작업은 완료됐지만 로그인 상태를 확인하지 못했다고 안내한다.
- 완료한 작업을 다시 제출하지 않고 세션 확인 재시도 또는 로그인으로 복구한다.
